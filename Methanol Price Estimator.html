Methanol Price Estimator

R² 0.833 · MAE $29.96/MT · built by Reid Powning
I built this to teach myself how methanol prices actually move, using real pulled data — FRED for natural gas, crude oil, the dollar index, housing starts, China industrial production, and gasoline, merged with Methanex's historical posted price by region, plus price from 1, 3, and 12 months back as extra features. The model landed at R² 0.833 and about $30/MT average error on months it hadn't seen during training — I'm pretty happy with that for a first pass with a plain linear model.
Thing I found while digging into this: the coal-vs-natural-gas feedstock feature came out to a coefficient of exactly 0. At first I thought I'd broken something, but it turns out FeedstockType is fully determined by Region in my data — China always maps to coal, everywhere else maps to natural gas — so the model literally can't tell the two apart and folded that whole effect into the Region numbers instead. Kept feedstock visible below since it's still useful context, just know it isn't doing anything to the math on its own.

HOW I BUILT THIS
01
Started with "what actually moves this price" instead of "what data can I find"
I didn't want to just grab whatever columns were easy to pull, so I forced myself to think through the mechanism first: split candidates into cost-push stuff (feedstock and input costs — natural gas, crude oil, dollar strength) and demand-pull stuff (the industries that actually consume methanol — housing starts as a formaldehyde proxy, China industrial production, gasoline price as a blending proxy). That framing is what told me which real data series to go find later.
02
Built the whole pipeline on made-up data first
Before touching any real APIs, I generated a synthetic dataset with realistic correlations baked in on purpose. That let me build and debug the whole pipeline — null handling, one-hot encoding, scaling, train/test split, model fit — against data I knew would behave, instead of fighting data-quality issues and modeling issues at the same time.
03
One-hot encoded the categorical columns
Region (North America / Europe / Asia Pacific / China) and FeedstockType (Natural Gas / Coal) don't have any natural order to them, so I ran each through scikit-learn's OneHotEncoder: pulled the column into a list, wrapped it as a list-of-lists since that's the 2D shape it wants, called .fit() to learn the categories, then .transform().toarray() to get the 0/1 columns back and concatenated those onto my features, dropping the original text columns.
04
Standard-scaled the numeric columns
Ran every numeric feature (natural gas, crude oil, USD index, housing starts, China industrial production, gasoline, and later the lag prices too) through StandardScaler so each ends up with mean 0 and standard deviation 1. Without this, housing starts — which sits in the thousands — would completely swamp something like natural gas price, which is single digits, purely because of the units they're measured in, not because it's actually more predictive. This is also the reason the dashboard's math below has to "un-scale" every slider value using the exact same mean and scale from training, instead of just plugging raw numbers into the coefficients.
05
Split the data by date, not randomly
This is time-series data, not independent rows like individual house sales, so a random shuffle split would let future months leak into training and make the model look better than it actually is. Instead I sorted everything by date and trained on the earliest ~80% of months, testing on the most recent ~20% — closer to how I'd actually use this: predicting forward from what already happened.
06
Swapped in real data once the pipeline worked
Pulled the feature data from FRED's API (natural gas, crude oil, USD index, housing starts, China industrial production, gasoline — resampled to monthly with .resample("MS").mean() so everything lines up on the same date index) and got the actual methanol price from Methanex's historical posted price file. Had to melt that from wide format (one column per region) into long format (one row per Region + Date) to get the same Region column I'd already built the pipeline around.
07
Added lagged price as a feature
My first pass with just macro features wasn't picking up as much as I wanted, so I added MethanolPrice shifted back 1, 3, and 12 months as extra columns. Figured recent price would probably matter a lot for a commodity like this, and it turned out to be an understatement — the 1-month lag ended up with by far the biggest coefficient in the whole model.
08
Kept the model itself simple and read into the coefficients
I went with plain LinearRegression instead of something fancier, since what I wanted out of this was an interpretable baseline I could actually understand — not squeeze out every last point of accuracy. That choice is what let me catch the multicollinearity between Region and FeedstockType mentioned up top; a more of a black-box model would've just hidden that.
09
Ported the trained model over to build this dashboard
Everything above happens once, in Python, inside my notebook. This page doesn't run Python or call scikit-learn at all — it's a plain HTML/JS file where I copied the trained model's coef_, intercept_, and the StandardScaler's mean_/scale_ straight out of the notebook and hardcoded them into the MODEL and SCALER objects in the script. Every time you move a slider, it's rerunning the same scale → multiply-by-coefficient → sum → add-intercept math that model.predict() does in Python — just in JavaScript, so it feels instant in a browser.
